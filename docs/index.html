hwcase

Lay real hardware out in 3D, check that the plugs and cables can physically get where they need to go, and get a case you can actually have made: laser-cut layers, or a Eurorack frame from extrusion and folded sheet.

What it is

Box generators make empty boxes. PCB tools lay out components inside a board. hwcase covers the gap between them: you have eight boards on the bench, and you want a case around them that does not block the HDMI port.

There are two kinds of project. The editor asks which one you want when a project begins, and the choice is fixed after that, because the two have nothing in common to convert.

Laser-cut layered case

You place the boards. The case is generated around them as a stack of flat sheets, with a pocket, a window or a cable opening wherever the hardware needs one.

Output: SVG or DXF sheets sized to your cutting bed, plus a cut list.

Eurorack U-profile case

You set a width in HP, a depth, and a stack of rows. The frame follows from the format: rails, one folded aluminium body, and two side panels that drill themselves.

Output: a side-panel SVG, and the numbers to order the rest.

Both share one editor, one file format and one server. All geometry is computed by a Python engine; the browser only draws what the engine returns, so what you see and what you cut cannot disagree.

Install and run

Windows

start.bat

That is all. On the first run it builds a .venv folder beside itself and installs the requirements, which takes about two minutes. It then finds a free port from 8487 upward, starts the server and opens the browser. Later runs take a few seconds. It needs Python 3 on the machine and touches nothing outside its own folder.

CommandWhat it does
start.batFirst free port from 8487, opens a browser, reloads when the engine changes
start.bat 9000Uses the port you give it
start.bat 9000 bareNo auto-reload and no browser
start-hosted.batThe same server the way a public instance runs it, on port 8497. See Hosting

Linux and macOS

There is no launcher script, but the steps are short:

python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cd backend
../.venv/bin/python -m uvicorn hwcase.api:app --port 8487

Then open http://127.0.0.1:8487.

Docker

docker build -t hwcase .
docker run --rm -p 8000:8000 hwcase

The image runs in hosted mode by default, which stores nothing. See Hosting for the single-user variant with a mounted project folder.

The photographic renderer (optional)

.venv\Scripts\python -m pip install mitsuba

About 50 MB. Everything else works without it, and the editor hides the render button when it is missing. On startup Mitsuba prints jitc_llvm_init(): LLVM API initialization failed; that message is harmless.

Moving and snapping

Selecting a part puts a gizmo on it: an amber pivot for sliding and a blue ring for turning. The ring is a fixed size, so it is the same target on a 25 mm breakout as on a 128 mm panel.

Snapping is on by default. While you drag, the moving part's edges and centreline are matched against every other board's, and the nearest match within 2 mm wins, independently in X and Y. A green guide shows what it caught. This is how two 60 mm keypad boards end up exactly 60 mm apart. A snapped coordinate is kept exact, not rounded.

The 90° buttons snap to an absolute multiple of 90. If you free-rotate to 37° and press one, you land on 0° or 90°, never 127°. Rotation pivots on the part's own centre.

A part mated to another, such as a screen plugged into a Pi, cannot be dragged on its own. Clicking any board in a mated stack moves the whole stack.

Parts named by an error are drawn ghosted red. The case outline and the issue list update while you drag.

Scenes and files

A project is a scene: one YAML file. The file menu offers new, duplicate, rename, save as and delete, plus open a file and save to a file for moving a scene between machines.

  • Run locally, scenes live in backend/scenes/.
  • Saving keeps the file's comments. New values are merged into the existing document, so notes you wrote in the file survive an edit.
  • Duplicating and renaming copy the file itself, comments included.
  • Scene names become file names. Letters, digits, spaces, dot, dash and underscore are allowed. Creating or renaming onto an existing name is refused.

How a layered case works

A case is a stack of slabs. Each slab is one sheet of material and one 2D shape: the outer outline, minus the pockets the hardware needs at that height, minus the corridors the connectors need through the walls.

Cut the stack on a laser and it is the case. The same model also serves a 2.5D milling job or a 3D preview, because it is all 2D polygon arithmetic. That is also why it is fast enough to recompute on every drag.

The working loop

  1. Add parts from the palette. What is listed there has been measured. The search box under it reaches the rest of Adafruit's catalogue.
  2. Arrange them by dragging. A part carries its real volumes (sockets, glass, knobs), so the case knows what to avoid, not just how big the board is.
  3. Check the issues pane. It reports collisions, plugs that cannot be inserted, cables with no room, controls you could not reach, and numbers that are still guesses.
  4. Cut: export SVG or DXF.

The checker is the point of the tool. In the demo scene the Raspberry Pi is rotated 180° because, the other way round, the checker reported that four USB plugs needed 45 mm of straight run through the keypads.

Heights and panels

You should not have to type a height. A panel is the surface your eyes and fingers meet, and it is derived from the part that fixes it:

panels:
  - name: main
    from_ref: screen.active_area     # the screen glass fixes the face

Every other part then says which of its own features must sit flush:

  - id: encoders
    part: adafruit-5752-quad-encoder
    on_panel: main
    panel_ref: bushings     # the collar clamps the panel; the shaft stands proud

Change the spacer under the screen and the panel moves, and every keypad, knob and window moves with it.

SettingMeaning
mount: autoThe default. A board with anything facing up goes to the panel; anything else rests on the floor
mount: panel / floorForce one or the other
mount: manualUse the Z in pos exactly as written
panel_refA volume name in this part or in anything mated on top of it; top for the highest point; auto for the highest control or display
panel_offsetPositive stands proud of the panel, negative sits recessed
under_panel: trueThe faceplate passes over this board unbroken. No window or hole is cut for it

A display recessed below the faceplate gets its window cut through every layer above the glass, so it looks out through a well. The checker warns when a control ends up below its panel, because you could not press it.

Mates

Two parts with a matching connector standard can be snapped together. The child is positioned by the solver, and you set only the gap:

  - id: screen
    part: hyperpixel4-square-touch
    parent: pi
    parent_mate: gpio40
    mate: gpio40
    mate_gap: 17.0          # the header stack between the two boards

Features that repeat

A 4×4 keypad is sixteen 10 mm buttons on a 15 mm pitch, not one 55 mm square. Volumes take a repeat grid and a shape:

      - name: buttons
        at: [30.0, 30.0]
        size: [10.0, 10.0]
        corner_radius: 1.5
        repeat: {count: [4, 4], pitch: [15.0, 15.0]}   # centred on `at`
      - name: bushings
        size: [6.8, 6.8]
        shape: circle
        repeat: {count: [4, 1], pitch: [19.05, 0.0]}

Instances are named buttons[2,3] in the issue list.

Getting cables out

How a port gets out of the case is decided per side of a board:

  - id: pi
    part: rpi-3b
    sides:
      - side: -y
        cutout: open_side
        headroom: 2.0
        span: full
      - side: +x
        cutout: per_connector
        include: [usb1, hdmi]     # only the ports you actually use
cutoutWhat the case does
noneLeaves the wall solid on this side
per_connectorOne opening per port, sized for the plug and its cable bend. The default
open_to_edgeThe same openings, run out to the edge as slots
channelA groove channel_width wide from each port out through the wall, open down to the underside
open_sideOne opening spanning all selected ports of that side, open to the underside
OptionDefaultMeaning
includeevery external portWhich of that side's connectors count. Name a list to drop a port you never use, or add an internal one
marginunsetMaterial between this side's outermost port and the outside of the case. Unset, the wall lands where the global wall puts it, which can bury a port on an inner board
channel_width10Width of a channel, mm
headroom2Clearance above and below the ports for open_side and channel, mm
spanportsWidth of the opening: ports, board or full

A connector can also ask for a round hole with cutout_shape: circle, which is what a 3.5 mm jack wants. An explicit cutout size on a connector is treated as a measurement and is never widened.

The interior

Internal cables need somewhere to run. Left solid, the middle layers are a block with a pocket per board. Hollowed out completely, the faceplate has nothing holding it up. So the interior is a choice, from the dropdown in the header:

interiorThe middle layers becomeMaterial left
pocketedSolid, one pocket per part, corridors for the external ports. The default75%
grownPockets grown to clear every cable port and the clearance around each board66%
ribsHollow, plus stiffeners on a grid, routed around hardware and cables27%
hollowA wall all the way round, empty inside12%

The last column is measured on the demo scene, relative to solid. The floor and the lid keep their own rules whatever the interior is.

The stack is sized from the lowest board. Anything hanging below a board, such as an SD card or a pin row, pierces the base plate as an opening instead of costing a whole spacer layer.

Screws and bolts

Carrying a board by its mounting holes

Per placement, support decides whether the case holds the board:

supportWhat the case grows
noneNothing. The default
from_floorA column from the bottom plate up to the board's underside, with a clearance hole through it
from_lidA clearance hole down through the faceplate, so the board is screwed up against its underside

screw_inset decides whether the head sinks into the outer plate. Left unset it follows the direction: flush for from_floor, so the case does not rock on the bench, and proud for from_lid, because a counterbore there would leave the head nothing to bear on.

One screw length: wells

On by default (screw_wells). The head-diameter bore continues through every layer of a support column except the one directly against the board. Every screw then spans exactly one sheet plus the board, so one screw length fits every board in the case, however deep each sits.

Case bolts

Bolts through the whole stack clamp it together. Choose none, corners or perimeter in the case pane, with an optional centre bolt for a wide lid.

Each bolt carries a collar of material on every layer, 9 mm by default. Without it, a hollow layer has nothing at that point and the hole would simply be absent from the sheet. A bolt that would land on a board is reported, not drilled.

What the engine guarantees

Three checks run on the finished geometry, whatever interior you chose.

  • The material is one piece. Nothing comes off the cutting bed as a separate part. A post holding a board up is tied back with a rib; loose debris is dropped.
  • The empty space is one piece. Every internal lead can reach every other one. Where a board would be walled in, a groove cable_channel wide is cut. Turn this off with link_cables: false.
  • Nothing is too thin to survive. Material narrower than min_segment (4 mm by default) is opened out, so two close cutouts become one opening instead of leaving a thread of plywood. Set it to 0 to disable.

Screw seats are re-checked after everything else has run. If a later step carves one away, the build says so with coordinates.

Case size and anchors

By default the outline is the bounding box of the hardware plus the wall. That is right while laying out, and wrong once you want a connector flush with the outside: push a board outward and the wall moves with it.

The case size control switches the outline to fixed. The current shape is frozen, and from then on moving a board moves it relative to a stationary wall.

anchor re-centres the scene on one placement at every solve. That placement then cannot be dragged, because dragging it slides everything else the other way. The checker warns about an anchored part that is not locked.

Engraving

A laser does two jobs. A cut goes through the sheet. An engrave marks the surface. Engraving is kept in its own group in the SVG (blue, titled "do not cut") and its own _ENGRAVE layer in the DXF.

Seven patterns, from the decoration section of the case pane:

PatternWhat it draws
textLettering in a single-stroke font
finsParallel fins, the amplifier front-panel look
slotsRounded slots in offset rows, like a speaker grill
ringsConcentric rings
hexA hex mesh
ruleOne hairline, for separating groups of controls
frameA border following the region's edge

Labels

  • Labels use the Hershey stroke fonts, so the laser follows the centre line of each letter in one pass. Two weights are included: light and medium.
  • text_size is cap height in millimetres, the dimension you measure on the finished panel.
  • A label is never scaled to fit its box. It overhangs and reports by how much.
  • A character the font does not have is skipped, not replaced by a box.

Marks are clipped to the plate. face chooses the faceplate (lid) or the back plate (floor).

cut right through moves a pattern out of the engraving pass and into the geometry. Whether the panel still holds together afterwards is not checked.

Exporting for the laser

Export splits the cut into bed-sized sheets: one file per bed-load, plus a cutlist.txt naming which layer is on which sheet, its size, and whether it was rotated.

Plate stock

The sheet section of the case pane holds the plate sizes you have. One entry (350 × 350 mm by default) means every sheet is that size. Add more entries for offcuts. Parts are placed largest first, and a new plate is always the smallest one that fits, so offcuts are used before a full sheet is broken. The cut list opens with a line saying how many of each size to fetch.

  • Margin (5 mm) and part spacing (4 mm) apply to every plate.
  • Parts are rotated 90° automatically when that fits better.
  • A layer that fits no plate is refused, with its size in the message.

How the files are written

  • Each sheet file is exactly the bed size. No sheet outline is drawn, because a cutter that runs every path would cut it.
  • Cuts are red. Engraving is blue, on its own DXF layer.
  • Every hole comes first and every outer edge last. Path order is cut order on many machines, and an outline cut early drops the part out of the sheet before its holes exist.
  • Outlines are kerf-compensated using the material's kerf.

Chrome and Edge ask for a folder and write the files into it. Firefox has no folder picker, so the same files arrive as one zip.

Rendering

The render toggle swaps the schematic view for a physically based one, with a sun you steer using three sliders (azimuth, elevation, strength).

  • Light comes from one of four environments: a built-in synthetic room, and three captured ones (studio, daylight, dusk).
  • Contact darkens the seams between slabs, which is what makes a stack read as separate sheets.
  • Finish comes from the material's name: plywood-3mm is matte, acrylic-clear-3mm is glossy and see-through, aluminium-2mm is metallic. A color in the scene overrides the preset's colour and keeps its feel.

The final photograph

render a photograph in the look pane ray-traces the scene on the server with the same environment the preview uses. It takes minutes. A 1100 × 825 image at 96 samples takes about 35 seconds on a laptop. It needs the optional Mitsuba install. Acrylic is rendered as real glass-like material, with refraction and edge glow.

How a frame goes together

A Eurorack frame's shape is decided by the format before any module exists. Nothing is placed by hand. The case is made of three kinds of piece:

  • Rails. One aluminium extrusion, two per row, cut to the case width. The rail is the case's visible front edge, not something hidden inside it.
  • The body. One folded 1.0 mm aluminium U, whatever the height. Its two flange edges slide into the rails' sheet slots. It is a skin, not a chassis.
  • Two side panels. 5 mm plate, and the only structural member. Every rail is bolted between the panels with one M5 screw per end.

The model is built around specific stock: the f&w rail Art. 16500 ("Eurorack-Rail mit Kante"), a 1.0 mm aluminium U-channel folded to order, and 5 mm plate for the side panels. Using a different rail profile means changing the constants at the top of backend/hwcase/rack.py.

Everything is in the frame pane, and in the scene file under rack:.

  module_depth: 51.0

Worked examples

All at 68 HP, 51 mm module depth and the default 10.5 mm panel margins.

Rail length is 345.44 mm and outer width 355.44 mm in all three. The M5 holes sit 6 mm behind the module face, in the solid part of the rail in front of its slot.

The 1U + 3U + 1U row matches the hand-built reference case: a 216 mm web and a 237 mm side panel. The hole positions differ from that case by up to about a millimetre, because it was drilled to whole-millimetre spans (35 / 123 / 35) and the tool uses the exact rack arithmetic (33.6 / 122.5 / 33.6).

Stance and corners

The rail stands 2.7 mm proud of the body. What the case rests on follows from the side panel's bottom margin:

Bottom marginThe case stands on
Under 2.7 mmIts rails (aluminium)
2.7 mm or moreIts side panels. This is the default, at 10.5 mm

The top and bottom margins are raised automatically to 2.2 mm if they are set lower, because below that an M5 hole would run off the panel's edge. The frame pane says when it has done this, and which stance you ended up with.

Front and back margins are pure lip. Each of the four corners takes its own radius. Two radii on one edge that add up to more than the edge are refused.

Side panel inserts

With inserts_per_row: 1, each side panel gets a slot per 3U row. The slot is 4 HP across (20.32 mm) and 112 mm long, centred on its row, and it breaks the panel's back edge so a module can slide in from the side.

That adds 4 HP on each side, so 8 HP per 3U row, without widening the rails. A 68 HP frame with inserts holds 76 HP per 3U row. 1U rows get no slot.

Getting it made

The result block at the bottom of the frame pane lists every derived number: height in U, rail span, outer width, depths, web, panel height, rail and screw counts, capacity, and the rail slot centres measured from the panel's bottom edge.

PieceHow you get it
Side panelsexport side panels (SVG). Both panels in one file, holes before outlines, kerf-compensated by 0.15 mm
BodyThe order the U-channel block: length, widths A / B / C and thickness, which are the fields a folding shop's form asks for
RailsBought by length. The count and the length are in the result block
ScrewsOne M5 per rail end

For a 68 HP, 6U frame at 46 mm module depth, the U-channel order reads: length 345.4 mm, A 35.0, B 260.5, C 35.0, thickness 1.0, folded from a 330.5 mm flat.

Check before ordering. One constant in the model is fitted from a single built case and not yet confirmed with calipers: the 2.3 mm from the outermost rail slot centre to the body's edge. It sets the web height. Measure your own rail before committing to a folded part.

The part library

Parts are data, not code. Each is a YAML entry in backend/parts/ describing one physical board: its outline, the volumes that stand off it, its connectors, mounting holes and mates.

The library ships with nine parts: Raspberry Pi 3B, Pimoroni HyperPixel 4.0 Square, Adafruit 1.5" OLED, NeoTrellis, the elastomer keypad, the quad encoder strip, the Shorepine AMYboard and its Eurorack panel, and the Seeed Grove I²C hub.

Confidence

Every number carries where it came from. The issues pane reports anything that is still a guess.

TagMeaning

Coordinates

In a part file, X and Y lie in the board plane and +Z points out of the component side. z = 0 is the bottom face of the PCB. The board occupies [0, pcb_thickness], and a datasheet height quoted from the board surface is pcb_thickness + height. All lengths are millimetres and all angles degrees.

      size: [60.0, 40.0]
      corner_radius: 2.0
      origin: min              # local origin at the lower-left corner
    pcb_thickness: 1.6

    holes:
      - {at: [3.0, 3.0], diameter: 2.7, screw: M2.5}

    volumes:

        kind: actuator

Importing from a catalogue

The find a part box searches Adafruit's live catalogue, about 5,500 products. Around 470 of them have a vendor CAD model, and the search says which. A product with a model can be measured automatically.

The catalogue is cached on disk and refreshed daily, so search works offline and survives the vendor's site being down.

An import gives youStatus
The outline, board thickness and the volumes standing off the boardReal, from the model
The mounting holesReal, from the STEP file
Which way up the board isGuessed, and labelled as a guess
What each volume isUnknown. A box is known to be there, not that it is a socket
ConnectorsNone

A freshly imported board has no connectors, so it asks the case for no cable room at all until you add them.

Run locally, imports are written to backend/parts/imported.yaml and join the palette. On a hosted instance they go into the scene file instead.

Measuring CAD by hand

python tools/fetch_cad.py 3954 4741 5752
python tools/measure_cad.py --band 0.8 "vendor/cad/adafruit/5752/*.stl"
python tools/extract_holes.py "vendor/cad/adafruit/3954/*.step"

The first downloads vendor models, the second prints dimensions and height profiles, and the third reads mounting-hole positions out of a STEP file.

Auditing the library

python -m hwcase.cli audit
python -m hwcase.cli audit --tolerance 0.5 --strict

This re-measures every part that names a cad: file and reports where the part file and the model disagree: outline, board thickness, and how far anything stands proud. Worth running periodically, because vendors revise boards and quietly replace their models.

Command line

Run from the backend folder.

python -m hwcase.cli parts                              # list the library
python -m hwcase.cli check scenes/soundmachine-v0.yaml  # report problems
python -m hwcase.cli build scenes/soundmachine-v0.yaml -o ../out
python -m hwcase.cli audit                              # library vs vendor CAD
CommandOptionsWhat it does
partsLists every part with its size, height and weakest confidence
check <scene>--strict exits non-zero on errorsResolves the scene and prints extent, panels and issues
build <scene>-o DIR, default outWrites *-layers.svg, *-layers.dxf, *-scene.json and *-case.json
audit--tolerance MM (0.3), --strictCompares parts against their vendor models

--parts DIR before the command points at a different part library.

The command line builds layered cases only. Run on a kind: rack scene, check reports an empty scene and build writes an empty two-layer case instead of a frame. Build frames from the editor or the HTTP API.

HTTP API

The editor talks to a FastAPI server. Every route that does real work takes the whole scene as JSON in the request body and reads no file to answer, so the API is usable on its own. Interactive documentation is served at /docs on a running instance.

Engine

RouteReturns
POST /api/resolveResolved placements, issues and the scene's extent
POST /api/buildThe layer stack for a layered case, or the members, bill of materials and order numbers for a frame
POST /api/case/freezeThe derived case outline turned into a fixed one
POST /api/export/svgAll layers as one SVG
POST /api/export/dxfAll layers as one DXF
POST /api/export/sheets/{svg|dxf}Bed-sized sheets and a cut list, as a zip, or as JSON with ?as_json=true
POST /api/export/rack/panels.svgA frame's two side panels as one SVG. Frame scenes only
POST /api/renderA ray-traced PNG. Query: samples, width, height, env, elevation, azimuth
GET /api/render/statusWhether the renderer is installed, and which environments exist

Example: build a frame

curl -X POST http://127.0.0.1:8487/api/build \
  -H "Content-Type: application/json" \
  -d '{"name":"f","kind":"rack","rack":{"hp":68,"module_depth":46,
       "rows":[{"format":"3U"},{"format":"3U"}],"inserts_per_row":1}}'

The response carries width, web, panel_height, depth, stands_on, bom, order, rows and one entry per member with its outline and holes.

Hosting

GitHub can host the code and this documentation, not the editor. GitHub Pages serves static files only, and every piece of geometry is computed by the Python server. To put the editor online you need a machine that can run Python or Docker.

Publishing this page with GitHub Pages

In the repository on GitHub: Settings → Pages → Build and deployment → Deploy from a branch, choose the main branch and the /docs folder. This file is self-contained, with no external assets.

Two modes of one program

Hosted mode keeps nothing on the server: no scene storage, no writable part library, no output files, no accounts. Run start-hosted.bat before deploying to see exactly how it behaves.

A visitor's project lives in the browser's local storage, which does not survive clearing site data and does not exist in a private window. The durable copy is the file from file → save to a file. Tell people to keep it.

Running a public instance

HWCASE_SITE=case.example.com docker compose up -d --build
./deploy/update.sh --pull        # for every change after the first

The compose file puts a Caddy reverse proxy in front for TLS, a request size cap and rate limiting. With HWCASE_SITE unset it serves http://localhost:8080 without a certificate. update.sh rebuilds, restarts, and waits for the new container to answer before calling it done.

One user, in Docker

  -v "$PWD/my-project:/app/backend/scenes" hwcase

The image sets hosted mode, so it has to be cleared explicitly. The mounted folder must be writable by uid 10001.

Known limits

  • Frames are not in the command line. They build from the editor and the API only.
  • No drill list for rails. The frame exports its side panels and the U-channel order numbers. Rails are listed by count and length only.
  • One rail profile. The frame model is built around f&w Art. 16500.
  • No joinery. Layers are held by bolts. Kerf is modelled; finger joints are not.
  • No solid export. There is no STEP output for milling or printing yet.
  • Cables are a clearance, not a route. The engine reserves room and connects the empty space, but does not plan a path or check cable lengths.
  • Sheet packing is rectangular. Layers are shelf-packed, not nested into each other's concavities.
  • One catalogue. Search and import cover Adafruit only.
  • It does not check your wiring, and it does not know that a board needs airflow.
